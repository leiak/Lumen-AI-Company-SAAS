# 附录 E：数据流全景示例

> 本附录用一个完整 HTTP 请求作为示例，**端到端追踪**它从浏览器进入到落库的全链路。
> 这是排查问题、Code Review、性能优化的统一参考。

---

## E.0 场景描述

**用户操作**：HR 专员张三（`user_id=1001`，`tenant_id=1`）打开员工列表页，查询部门 = "研发部" 的所有在职员工。

**HTTP 请求**：

```
GET https://lumen.com/hr/employee/list?dept_id=100&status=ACTIVE&pageNum=1&pageSize=20
Headers:
  Cookie: ACCESS_TOKEN=eyJhbGc...; REFRESH_TOKEN=eyJhbGc...
  User-Agent: Mozilla/5.0 (Windows NT 10.0; Win64; x64) Chrome/...
  Accept: application/json
  X-Forwarded-For: 192.168.1.100
```

**期望响应**：

```json
{
  "code": 0,
  "message": "ok",
  "data": {
    "total": 152,
    "pageNum": 1,
    "pageSize": 20,
    "rows": [
      { "id": 10001, "code": "E001", "name": "李四", "deptId": 100, "postName": "Java 工程师", "status": "ACTIVE", ... },
      ...
    ]
  },
  "traceId": "abc123def456"
}
```

## E.4 失败场景示例

### 场景 1：Token 过期

```
1. 用户 Cookie 中 ACCESS_TOKEN 过期
2. Gateway 鉴权过滤器 → 401
3. 前端 Axios 拦截器检测到 401
4. 自动调用 /auth/refresh 刷新 Token
5. /auth/refresh 失败（Refresh Token 也过期）
6. 前端清除本地状态，跳转登录页
7. 整个过程对用户透明或提示"会话过期，请重新登录"
```

### 场景 2：Sentinel 触发限流

```
1. 某租户在 1s 内发起 250 个 hr.employee.list 请求
2. Gateway Sentinel 限流规则：QPS ≤ 200
3. 多余 50 个请求被拒绝
4. 返回 429 + code="99D001" + message="系统繁忙，请稍后重试"
5. 前端展示友好错误提示
6. 触发告警（钉钉群）
```

### 场景 3：MySQL 慢查询

```
1. MySQL 检测到 query_time > 1s 的查询
2. 写入 slow_query.log
3. 触发告警（钉钉群 + 短信）
4. 自动诊断：
   a. EXPLAIN 找出全表扫描
   b. 推荐索引：DBA 收到工单
   c. DBA 添加索引（DDL 走 Flyway V1.5.0）
5. 下次查询 < 100ms
```

### 场景 4：租户越权

```
1. 某用户尝试访问其他租户数据：
   GET /hr/employee/list?X-Tenant-Id=999   （伪造 Header）
2. Gateway 多租户解析器：以 JWT 中的 tenantId=1 为准
3. SQL 注入：WHERE tenant_id=1（不是 999）
4. 返回数据只包含 tenantId=1 的数据
5. 如果用户没有该租户权限 → 返回空列表（不是 403，避免探测）
6. 操作审计记录：尝试越权 → 安全告警
```
