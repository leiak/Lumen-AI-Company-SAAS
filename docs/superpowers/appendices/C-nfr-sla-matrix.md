# 附录 C：非功能性需求矩阵（NFR）+ SLA

> 本附录定义 17 个子模块 + 6 个基础服务的**非功能性需求**：
> 性能（P50/P95/P99 响应时间）、可用性（SLA）、数据量级、并发、灾备指标。

---

## C.1 总目标

| 维度 | 目标 | 度量 |
|---|---|---|
| **系统可用性** | ≥ 99.9%（年宕机 < 8.76 小时） | 全年统计 |
| **核心业务可用性** | ≥ 99.99%（年宕机 < 52 分钟） | 财务/HR/审批 |
| **数据持久性** | ≥ 99.999999%（多副本 + 备份） | 5 个 9 |
| **RPO** | ≤ 15 分钟 | 增量备份周期 |
| **RTO** | ≤ 4 小时 | 业务恢复时间 |
| **峰值并发用户** | 1000（中型 500-3000 人企业） | 同时在线 |
| **日请求量** | 500 万（峰值 1000 万） | 全站 |

## C.4 性能测试要求

### C.4.1 压测标准

每个服务上线前必须通过压测：

| 阶段 | 工具 | 目标 |
|---|---|---|
| **基准测试** | JMeter / wrk | 单接口极限 QPS |
| **容量测试** | JMeter Cluster | 200% 峰值 QPS 不报错 |
| **稳定性测试** | JMeter | 100% 峰值 QPS × 24h |
| **浪涌测试** | JMeter | 0 → 峰值 0 循环 100 次 |
| **故障注入** | ChaosBlade | 杀进程/网络延迟/磁盘满 |

### C.4.2 压测指标

| 指标 | 计算 | 目标 |
|---|---|---|
| **TPS** | 1s 内完成事务数 | 满足 SLA 要求 |
| **响应时间** | P50/P95/P99 | 满足 SLA 要求 |
| **错误率** | 失败请求 / 总请求 | < 0.1% |
| **CPU 利用率** | 平均 | < 70% |
| **内存利用率** | 平均 | < 80% |
| **GC 暂停** | P99 | < 200ms |
| **DB 连接池** | 使用率 | < 80% |

### C.4.3 压测报告模板

```markdown
## 压测报告

### 场景
- 接口：GET /hr/employee/list
- 数据：3000 员工
- 模拟：500 并发用户

### 结果
- TPS：850
- P50：85ms
- P95：210ms
- P99：380ms
- 错误率：0.02%

### 结论
✅ 满足 SLA（要求 P95 < 500ms）
```

## C.5 安全等级要求

| 等级 | 服务/数据 | 要求 |
|---|---|---|
| **L4 极高** | 财务凭证、薪资、密码 | 加密存储 + 审计 + 操作二次确认 + MFA |
| **L3 高** | 合同、HR 档案、身份证/银行卡 | 字段加密 + 默认脱敏 + 导出审批 + 水印 |
| **L2 中** | 客户信息、采购数据 | 列表脱敏 + 权限控制 |
| **L1 低** | 字典、公开数据 | 普通鉴权 |

**详细安全设计**：见主 spec §7 + ADR-0011（数据权限）
