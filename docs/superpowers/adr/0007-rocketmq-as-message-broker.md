# ADR-0007: 消息队列 RocketMQ 5.x

## 状态
2026-09-18 已决策

## 背景
业务服务之间需异步解耦 + 关键场景需可靠投递（本地消息表 + 事务消息）。

## 决策
**RocketMQ 5.x** 作为消息中间件。

## 备选方案

| 方案 | 优点 | 缺点 | 决策 |
|---|---|---|---|
| **RocketMQ 5.x（✅）** | 阿里双 11 验证；事务消息原生；顺序消息；延迟消息 18 级 | 阿里系、社区国际化弱 | ✅ |
| **Kafka** | 高吞吐、生态成熟 | 事务消息弱、延迟消息不支持、运维复杂 | ⚠️ |
| **RabbitMQ** | 协议丰富（AMQP/MQTT） | 事务消息需插件、性能弱于前两者 | ❌ |
| **Pulsar** | 新一代设计（存储计算分离） | 国内案例少 | ❌ |

## 关键能力对照

| 能力 | RocketMQ | Kafka |
|---|---|---|
| 事务消息 | ✅ 原生 | ⚠️ 0.11+ 支持但弱 |
| 顺序消息 | ✅ | ✅（分区保证） |
| 延迟消息 | ✅ 18 级（1s/5s/10s/30s/1m...2h） | ❌ |
| 消息回溯 | ✅ 按时间回溯 | ⚠️ 按 offset |
| 死信队列 | ✅ | ❌ |
| 中文文档 | ✅ 完善 | ⚠️ |

## 使用场景

| 场景 | 用法 | 关键能力 |
|---|---|---|
| 跨服务事件 | 普通消息 + 本地消息表 | 可靠性 |
| 订单创建 → 库存/财务 | 普通消息 + 幂等 | 解耦 |
| 合同到期提醒 | **延迟消息**（30/15/7 天） | 延迟 |
| 薪资发放通知 | 顺序消息（按员工 ID） | 顺序 |
| 操作审计同步到 BI | 普通消息 + 批量消费 | 吞吐 |

## Topic 命名规范
`{module}.{event}.v{version}`，如：
- `hr.employee.created.v1`
- `proc.order.approved.v1`
- `fin.voucher.posted.v1`

## 消费可靠性
- **手动 ACK**：处理完成后再 ack
- **失败重试**：3 次本地重试 + 死信队列
- **幂等消费**：消费者用 `msg_id` 去重（DB 唯一索引）

## 集群配置
- NameServer：3 节点（无状态）
- Broker：3 主 3 从（同步双写）
- Console：1 节点（运维）

## 后果

### 优点
- 事务消息满足本地消息表场景
- 延迟消息免去定时扫描
- 死信队列提供兜底

### 缺点
- Broker 主从切换有秒级不可用
- Topic 数量过多影响性能（建议 < 500）

### 风险与缓解
- **风险**：Broker 磁盘满导致消息丢失
- **缓解**：磁盘监控 + 自动清理策略（保留 3 天）+ 重要消息同步刷盘
