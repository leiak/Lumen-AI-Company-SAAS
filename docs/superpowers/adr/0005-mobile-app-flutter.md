# ADR-0005: 移动端 Flutter 跨端方案（暂定）

## 状态
2026-09-18 暂定（待子项目 17 详细评估时可调整）

## 背景
需要为员工提供移动端体验，覆盖：审批、考勤打卡、消息、报表查询。
候选方案：原生 / 跨端 / H5 / 小程序。

## 决策（暂定）
**Flutter 3.x** 作为 App 跨端框架，与 H5（Vue 3 + Vant）配合。

## 备选方案

| 方案 | 优点 | 缺点 | 决策 |
|---|---|---|---|
| **纯原生**（Swift + Kotlin） | 性能最佳、原生体验 | 两个团队、两套代码、长期维护成本 | ❌ |
| **React Native** | JS 生态丰富 | 性能瓶颈、桥接问题、原生模块需自己写 | ⚠️ |
| **uni-app** | 学习成本低、Vue 语法 | 性能一般、大厂项目少用 | ⚠️ |
| **Flutter（✅ 暂定）** | 跨端一致、Skia 自绘性能好、单一代码库 | 包体积大（>20MB）、需学 Dart | ✅ |
| **纯 H5 + PWA** | 无需发版 | 体验差、系统能力受限（推送/扫码弱） | ❌ |
| **钉钉/企微/飞书小程序** | 复用宿主能力 | 依赖第三方平台、跨平台要写多套 | ✅ 并行 |

**并行策略**：
- 内部员工优先用**钉钉小程序**（最快上线）
- 高管/外勤用 **Flutter App**
- 临时场景（外部供应商）用 **H5**

## 后果

### 优点
- 单一代码库覆盖 iOS/Android
- Skia 自绘引擎保证 60fps 流畅度
- 热重载开发效率高
- 与 Vue 技术栈共存，团队易上手

### 缺点
- 包体积大（需评估是否做动态化方案）
- 部分原生模块（深度定制扫码、人脸识别）需写 Platform Channel
- 团队需学习 Dart 语言

### 风险与缓解
- **风险**：Flutter 大版本升级破坏性变更
- **缓解**：锁版本到稳定版（3.19+），每年评估一次升级
- **风险**：包体积 > 30MB 影响下载
- **缓解**：模块化拆分 + 动态下发

## 后续评估节点
子项目 17（mobile-integration）启动时，重新评估：
- 若团队 Dart 学习曲线过高 → 切换 uni-app
- 若企业内部已有 RN 团队 → 切换 RN
- 若仅需审批/打卡 → 钉钉小程序足够，App 可延后
